# Architecture Decision Updates — Readiness Review Outcomes

> Review board output · Date: 2026-07-06 · Companion to [ArchitectureReadinessReview.md](ArchitectureReadinessReview.md) and [ImplementationReadinessDecision.md](ImplementationReadinessDecision.md)

This document records every architecture decision that the readiness review forced: contradictions between source documents that required one answer, and missing decisions an implementer would otherwise have made ad hoc. Each decision was applied directly to the source documents in the 2026-07-06 mandatory-fix wave and — where decision-level — recorded as a new ADR row in [ArchitectureOverview §7](../../docs/architecture/ArchitectureOverview.md) (files under `/docs/adr/` are produced by the Phase-0 backfill task per [ADRProcess](../../engineering-operating-system/ADRProcess.md)).

## 1. New ADRs (ADR-015 – ADR-020)

| ADR | Decision | Forced by | Superseded ambiguity |
|---|---|---|---|
| **ADR-015** | Read models are projector-maintained plain tables with RLS (`rm_*`/`metric_facts` + watermarks), rebuildable from topic replay + canonical recompute. PostgreSQL **materialized views are forbidden for tenant-scoped data** — RLS cannot attach to them (FR-128). | DAR-02 + SCL-03 | DataFlow §4 (projector tables) vs DatabasePlan (`reports.mv_*` materialized views) — two incompatible read-model architectures, one of which silently bypassed RLS |
| **ADR-016** | Vector-store tenancy: pgvector (default) isolates via RLS on `ai.rag_chunk`; Qdrant (pluggable) uses **one collection per tenant** per embedding space (`eip_<tenantId>_<embeddingSpace>`), with the SPI-level tenant filter and result-side recheck retained as defense-in-depth layers. | MTR-01 + RAG-01 | SecurityModel §5 ("separate collections per tenant") vs RAGArchitecture ("one collection per model, shared, filtered") — a direct tenant-isolation contradiction |
| **ADR-017** | Transactional-outbox scope: outbox is **mandatory for domain, analytics, and job events**; raw intake (sync emitters + webhooks) publishes **directly** to `eip.raw.<connector>` with the staged `raw_*` row as durability and `staging.webhook_intake_buffer` as the Kafka-outage buffer. OutboxRelay runs in **both** runtimes, each relaying its own writes. | SBR-04 + EDA-01 | EventModel §9 ("no producer ever publishes directly") vs DataFlow Flows A/C (direct raw produces) — and a relay-runner contradiction that would have stalled eip-app events whenever workers were down |
| **ADR-018** | Object-storage tenancy: **shared buckets + mandatory tenant-id key prefix + application-enforced scoping** in the single storage service, with access audit. Per-tenant MinIO credentials are not used (accepted risk; the NFR-041 isolation suite gains a storage-prefix isolation test). | MTR-02 | SecurityModel offered "bucket-per-tenant **or** prefix + per-tenant credentials" — an undecided either/or on an isolation mechanism |
| **ADR-019** | Single canonical writer: **eip-ingestion owns all writes to canonical tables**. Derived fields (`work_item.blocked`, `deployment.caused_incident`, `release.readiness_score`) and agent-raised Risk rows flow through an exported `CanonicalEnrichmentService` in eip-ingestion's API package; enrichment writes touch only enrichment-owned columns and normalizer upserts never clear them. eip-analytics additionally gets **read-only** SQL access to canonical schemas (never `staging.raw_*`, never writes) via a dedicated grant. | SBR-05 + SBR-02 | DomainModel assigned derived-field writes to eip-analytics while the module rules forbade analytics writing canonical tables; analytics read access was simultaneously forbidden (ArchitectureOverview) and prescribed (BackendPlan/EventModel) |
| **ADR-020** | AI eval placement: the CC-5 **merge** gate runs deterministic prompt-contract tests (no live model). The model-based eval suite runs **nightly and at release gates** on reference hardware with the pinned local model — never on the PR merge path. | AIR-03 | AgentArchitecture implied per-merge CI evals against a pinned local model, contradicting TestingStrategy's nightly placement and air-gapped CI reality |

## 2. Clarifying decisions applied to source documents (no new ADR — refinements within existing ADRs)

| ID | Decision | Documents aligned |
|---|---|---|
| AD-2 | One producer/consumer truth: EventModel §3 gains an **Owning module** column (raw+domain → eip-ingestion; analytics.metrics → eip-analytics; ai.jobs/results → eip-ai; reports.jobs → eip-reports). **eip-app consumes no Kafka**: agent-run status is served by polling/LISTEN-NOTIFY on `agent_runs`; the SSE-on-Kafka bridge and the undeclared `eip.reports.triggers` topic are removed. Consumer-group names unified to the EventModel §8 catalog; read-model projectors run under `eip.analytics.read-models`. | EventModel, BackendPlan, ComponentModel, ArchitectureOverview |
| AD-9 | Erasure vs append-only audit: audit `details` carry **pseudonymous member references only**; Member PII lives in a dedicated mapping store that FR-142 erasure hard-deletes/crypto-shreds, leaving the audit hash chain intact and verifiable. | SecurityModel §11, DatabasePlan, DomainModel, OperationsGuide §3.4 |
| AD-11 | Capacity truth: all sizing/throughput statements anchor to NFR-003 (100k events/h ≈ 2.4M/day, 3× burst 15 min); the only larger figure is the explicitly-labeled ~10× internal fan-out/replay headroom in ArchitectureOverview D3. | PRD, DeploymentModel §5, ArchitectureOverview |
| AD-12 | Table ownership: DatabasePlan §2 is the single table→schema→owning-module catalog (every table exactly one owner: connectors → connector/checkpoint tables; ingestion → canonical + staging + external_ref; core → infra tables (outbox, dedup ledger, heartbeat, Quartz); analytics → metric/read-model tables; ai/reports/tenancy → their schemas). ComponentModel "Data owned" lists match it verbatim; missing tables added; ModuleOwnership gains the docs-lint subset rule. | DatabasePlan, ComponentModel, DomainModel, ModuleOwnership (EOS) |
| AD-13 | Agent job claim: commit-on-claim — the `eip.ai.jobs` consumer commits offsets once the run row is claimed; run state in the DB is the source of truth; crashes requeue via worker-lease timeout, not Kafka redelivery. Long agent runs no longer fight `max.poll.interval`. | AgentArchitecture §3.5 (new), DeploymentModel |
| AD-14 | Source identity: `ExternalRef.externalId` = immutable source id (Jira numeric id, GitHub node id); human-readable keys (`PROJ-1234`) move to a new `externalKey` attribute. Issue moves/re-keying no longer break identity. | DomainModel §12.1, EventModel examples |
| AD-15 | Consumer failure taxonomy: TRANSIENT_INFRA (retry, no DLQ) · DATA_POISON (DLQ immediately) · LOGIC_BUG (DLQ after maxRetries + alert) · UNKNOWN_SCHEMA (DLQ + alert, FR-038). | EventModel §10, DataFlow invariants |
| AD-8 | Injection-flagged RAG content: high-confidence detections are **quarantined** (never indexed; admin review queue, audited); low/medium-confidence content is indexed **with flags** and neutralized rendering. | RAGArchitecture §3.3, SecurityModel §8 |
| AD-10-adj | Additional mandatory clarifications applied without new ADRs: MCP server delegation & audit completeness (MCP-01/02/03), master-key **compromise** recovery distinct from rotation (SEC-01), audit DDL hash-chain columns (SEC-02), metric `definition_version` dimension before first partition (DAR-01), correlation-edge storage (DMR-03), WorkflowState re-anchoring to workflow/project scope (DMR-04), MemberIdentity re-partitioning rule (DMR-02), connector archetypes + dispatch model + deletion detection + full-sync duration reconciliation (CON-01..04, EDA-02), infrastructure alert-set completion + buffer bounds (FMA-02/03), single alert catalog (OBS-01), trace-sampling correction (OBS-02), upgrade-order reconciliation (DEP-01), non-GitOps migration gate (DEP-02), backup-target monitoring (DEP-03), scale-out seam documentation (SCL-02). | Per-fix targets — see the review documents' §8 tables (status columns updated after the fix wave) |
