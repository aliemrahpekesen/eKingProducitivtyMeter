## Goal

Real deterministic pipeline replacing the seed-only `rm_team_flow_current` placeholder:

```
simulation source → ingestion → normalization → cross-tool correlation
→ metric computation → metric_fact/read model → API → frontend card + evidence drill-down
```

No AI. No real Jira/Bitbucket/GitHub/GitLab/Sonar connectors. No frontend visual redesign. Team-level only.

## Architecture note (v0.1 — no redesign)

The documented transport is Kafka-async (EventModel). This slice runs the **same logical pipeline in-process, synchronously, and deterministically** (connector → `staging.raw_*` → normalizer → canonical → correlator → analytics compute → `metric_fact`), keeping the documented module boundaries (connectors emit raw only; `eip-ingestion` owns staging + canonical write side + normalizers; `eip-analytics` computes). **The async Kafka transport (topics, outbox relay, idempotent consumers) is deferred → [DEBT-017].** The SPI/ingestion/analytics interfaces are shaped so Kafka slots in behind them later. This is a transport simplification, not an architecture change.

## Increments (each committed separately)

- **INC-1 — Deterministic simulation ingestion.** A production-shaped simulation `Connector` (SPI in `eip-connectors`) emits Jira-like work items + transitions, SCM PRs + review activity, builds, and quality-gate records — with explicit cross-tool identifiers and blocked/review-wait/rework/normal patterns — through the real ingestion path (`RawSink` → `staging.raw_simulation`). Idempotent (content-hash + natural-key upsert; replay = no dupes), tenant-scoped (RLS), provenance-carrying (source_system, natural_key, external identity). Connectors do NOT write dashboard rows.
- **INC-2 — Normalize, correlate, compute.** Normalize raw → canonical (`work.work_item(+transition)`, `scm.pull_request(+code_review)`, `cicd.build`, `quality.quality_gate`), populate `core.external_ref`. Correlate work_item→PR→review→build→quality_gate; persist correlation evidence. Compute deterministic team-level friction components (cycle/active/waiting/blocked/review-wait time, rework, flow efficiency, blocked ratio, review-wait ratio) and a versioned **Engineering Friction v0.1 (EXPERIMENTAL)** composite → `analytics.metric_fact` + a computed read model. The friction API stops depending on seed-only `rm_team_flow_current`.
- **INC-3 — Evidence-backed API + frontend.** API exposes score/summary, component breakdown, worst-first ordering, dominant cause, simulation label, calc timestamp/version, and drill-to-evidence (transitions/PRs/review waits/builds/quality gates). Frontend card renders it (no visual redesign). Team-level only; evidence identifies source artifacts, never individuals.
