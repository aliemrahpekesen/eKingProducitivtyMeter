## Problem statement

Turn the friction read model into a visible, callable metric. `GET /api/v1/friction/summary` returns, tenant-scoped under RLS, the **engineering_friction** metric definition (name, purpose, formula, grain, caveats, gaming-risks) plus a **per-team** friction breakdown (WIP, WIP-limit breaches, oldest-in-progress age, review-queue depth) with a **deterministic** friction score, sorted worst-first (the "top bottleneck"). This is the first analytics surface and the seed of the hero dashboard.

## Architecture constraints honored

- **Deterministic** — the friction score is a pure, documented weighted function of the `rm_team_flow_current` signals; identical inputs → identical output; no AI, no randomness. The formula text is mirrored in the seeded `metric_definition.formula` so the registry and the code agree.
- **Team-level only (Law 6 / NFR-071 / FR-057)** — grain is `team`; `rm_team_flow_current` and `core.team` carry **no** member/individual data. Nothing ranks or scores a person. Release-blocking guardrail respected.
- **Real DB reads under RLS** — reads `analytics.metric_definition`, `analytics.rm_team_flow_current`, `core.team` via `TenantScopedJdbc` (RLS GUC bound per tx). Tenant A never sees tenant B's teams.
- **Simulation-seeded only** — demo teams + flow signals seeded under the `demo` profile (and in the integration test); **no** real connector data. No Jira/Bitbucket/Sonar connectivity, no ingestion pipeline.
- **No UI, no AI.**
- **Placeholder honesty** — this derives a friction *index* from the current-flow read model in the API read path. The real Friction compute (wait-time decomposition across the correlated flow graph, projected to `metric_fact`) belongs in the `eip-analytics` deterministic engine → **DEBT-013**.

## Acceptance criteria

1. `GET /api/v1/friction/summary` returns the `engineering_friction` metric definition (key, name, purpose, formula, grain, caveats, gamingRisks) + a per-team list (teamId, teamName, wip, wipLimitBreaches, oldestInProgressAgeSec, reviewQueueDepth, frictionScore), tenant-scoped under RLS.
2. The per-team list is sorted **deterministically** worst-first (frictionScore desc, then teamName, then id); `teamsReporting` = number of teams reporting flow.
3. Tenant isolation proven through the API: a request for tenant A never sees tenant B's teams/flow (integration test, app as NOBYPASSRLS `eip_app`).
4. The friction score is deterministic and documented: the same seeded inputs always produce the same scores (asserted with exact expected values).
5. OpenAPI 3 contract regenerated + committed; errors RFC 7807.
6. Demo data (business unit + teams + friction definition + flow rows) seeds under the `demo` profile only; deterministic.
