## Problem statement

A new engineer needs to go from a clean clone to a booted stack and an open PR without asking a human. Provide developer onboarding documentation covering prerequisites, local setup, the `make` workflow (`dev-up`/`dev-down`/`dev-urls`), backend/frontend build + local-validation commands, troubleshooting, known local limitations, and the contribution rules (branching, gates, the CLAUDE.md session ritual). Docs must reflect the **current working repo state** (backend + frontend scaffolds, CI pipeline, Compose dev stack).

CC-6 (docs only). No application code, no schema, no contract anchor. The `/docs` product-spec baseline is not touched — onboarding lives in root `/CONTRIBUTING.md` and the `/README.md` index.

Contribution rules link the gates ([QualityGatePolicy](../../engineering-operating-system/QualityGatePolicy.md)), branch naming ([BranchingStrategy](../../engineering-operating-system/BranchingStrategy.md)), and the [CLAUDE.md](../../CLAUDE.md) session ritual; all relative links resolve; no placeholders (docs-lint-clean once TASK-0008 lands).
