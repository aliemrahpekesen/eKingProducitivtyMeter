## Scope

`backend/eip-workers` currently has `build.gradle.kts` (already depends on `eip-ingestion`/`eip-ai`/
`eip-reports`) and empty `src/main`/`src/test` trees — no worker `main` class, no
`eip.boot-app-conventions`. This task: (1) applies `eip.boot-app-conventions` (mirror `eip-app`'s
convention plugin usage) so `eip-workers` builds its own bootable jar/container image; (2) adds a
worker main class that activates Kafka consumers for `eip.ai.jobs`/`eip.ai.results`/
`eip.reports.jobs` (topics pre-named in `BackendPlan §9`, not yet produced/consumed anywhere); (3)
CI/CD wiring (a second image build, per `RepositoryStructure`/`DependencyManagement` conventions) and
Helm values for a second deployment (`infra/helm/eip/values.yaml`).

## Not in scope

The actual agent-execution or report-job-processing business logic — this task builds the empty
runtime shell + topic wiring only. TASK-0031 (agent runtime) and TASK-0029/0033 (report job
processing) are the first real consumers to run inside it.
