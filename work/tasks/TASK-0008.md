## Problem statement

Automate the G7 docs-lint gate so documentation stays consistent forever: broken-link detection, requirement-ID resolution, FeatureCatalog count reconciliation, and canonical-value drift greps — the four checks named in [DocumentationStandards §4 / §L4](../../engineering-operating-system/DocumentationStandards.md). The check fails the PR on any violation and is green over the current (baseline-clean) doc set.

## Change class

CC-7 (standard CI/tooling). Adds a lint stage + scripts; no application code, no schema, no contract anchor.

## Acceptance criteria (from TaskSpecs)

1. docs-lint runs on every PR as a G7 stage and is green over the current (baseline-clean) doc set.
2. A PR adding a broken relative link is **blocked**; fix → green.
3. A PR adding a dangling `FR-999`/`ADR-099` reference is **blocked**.
4. A PR introducing a canonical-value drift is **blocked**.
5. All four DocumentationStandards §L4 checks are implemented and wired.

## Test plan / validation commands

- `python3 scripts/docs-lint/docs_lint.py` → PASS (exit 0) over the current doc set.
- Block-then-pass demos: inject (a) a broken link, (b) a dangling `FR-999`/`ADR-099`, (c) a GUC drift → each fails (exit 1) → remove → green (exit 0).
- CI: the `docs-lint` job runs `python3 scripts/docs-lint/docs_lint.py` on every PR.
