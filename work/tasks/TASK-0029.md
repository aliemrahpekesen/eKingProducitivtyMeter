# TASK-0029 — Report engine v2: job schema + state machine

- **id:** TASK-0029 · **sprint:** unassigned (claim when picked up) · **story:** ADR-027 §3 — add `reports.report_job`/`report_template`/`report_schedule`/`report_subscription` and the job state machine that future AI-composed report types will run through.
- **branch:** create `feature/TASK-0029-report-job-schema` off `main` when claimed
- **status:** NOT STARTED — **blocked on [ADR-027](../../docs/adr/ADR-027-phase-3-ai-core-architecture.md) being Accepted.** Do not claim before then.
- **depends on:** TASK-0028 (MinIO storage SPI — job outputs land as artifacts)
- **closes:** part of DEBT-021 ("job-runner state machine")

## Scope

New migration(s) adding `reports.report_job`/`report_template`/`report_schedule`/`report_subscription`,
shaped by the state machine `PENDING → RUNNING → VALIDATING → RENDERED → DELIVERED | FAILED`
documented in `DataFlow §7`/`DomainModel §11` — **that pair, not `DatabasePlan §3`, is the source of
record** for this shape (DatabasePlan has no DDL sketch for these tables). Populate
`reports.generated_report.llm_call_ids`/`citations`/`validation_status` for AI-composed report types
(these columns already exist on `reports.generated_report`, unpopulated since ADR-023 — no reshape
needed, this task only starts writing to them for the report types that will use them).

## Not in scope

The existing deterministic `EXEC_SUMMARY` path (`ReportGenerationService`, `ScheduledReportRunner`)
is **explicitly unaffected** — it stays synchronous/inline, `status` always `READY` immediately, no
`QUEUED`/`GENERATING` state ever reachable for it. This task adds the schema and state machine only;
no agent exists yet to actually produce an AI-composed report (that's TASK-0033) — this task's own
verification should drive the state machine with a stub/fake job, not a real agent.
