# TASK-0031 — Agent runtime skeleton

- **id:** TASK-0031 · **sprint:** unassigned (claim when picked up) · **story:** ADR-027 §5 — build the typed tool-calling agent runtime (`ai.llm_provider`/`agent_run`/`agent_step`) that TASK-0033's agents will run on top of, executed inside `eip-workers`.
- **branch:** create `feature/TASK-0031-agent-runtime-skeleton` off `main` when claimed
- **status:** NOT STARTED — **blocked on [ADR-027](../../docs/adr/ADR-027-phase-3-ai-core-architecture.md) being Accepted.** Do not claim before then.
- **depends on:** TASK-0027 (LangChain4j swap — the runtime is built on the LangChain4j-backed SPI, not the old JDK-`HttpClient` providers), TASK-0030 (`eip-workers` deployable — this is where agents execute)
- **closes:** prerequisite for TASK-0032/0033 — does not close a DEBT row directly.

## Scope

New `ai.llm_provider`/`ai.agent_run`/`ai.agent_step` tables (`DatabasePlan §2` already names these,
no DDL yet — this task writes it). The typed tool-calling contract sketched in
[AgentArchitecture §4](../../docs/ai/AgentArchitecture.md) (JSON-Schema in/out, RBAC requirement,
tenant scope, bidirectional schema validation, result-size limits, artifact sanitization) and the
`LlmProvider`/`ModelDescriptor` SPI sketch in its §7 (capabilities declared per-model before the SPI
is published under semver, per NFR-060). Per-run budgets (token/cost/time/steps) and hard-stop
guardrails per FR-088.

## Not in scope

RAG retrieval (TASK-0032), any specific named agent (TASK-0033), MCP client/server (Phase 4, out of
this ADR entirely). Build the runtime generic enough for tool-calling but do not wire a single real
tool yet beyond whatever minimal probe this task's own tests need.
