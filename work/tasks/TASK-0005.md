## Problem statement

Establish the `eip-core` shared-kernel **base types** every downstream module depends on — canonical identity (UUIDv7), `ExternalRef` provenance, the `WorkItem` type discriminator, the domain-event envelope, and the error-taxonomy root — plus a module-boundary test that keeps `eip-core` a **leaf forever** (AP-1). Skeleton only: no persistence, no Kafka, no SPI implementations, no business logic. Getting the contract right now is the point of the CC-1 gate.

## Change class

CC-1 (contract anchor: the shared kernel). Gates in force: G0 (+ CC-1 DoR R-CA approach pre-approval — recorded), G1, G2 (coverage ≥ 85%), **G4 (R-CA + R-BA)**, G7 (MODULE.md), **G8 (two approvals: R-CR + R-CA)**.

## Acceptance criteria (from TaskSpecs)

1. `ApplicationModules.of(...).verify()` passes; `eip-core` has zero dependencies on any other `eip-*` module (leaf invariant).
2. Base types compile and are `record`/`sealed`/`enum` per CodingStandards; UUIDv7 + UTC `Instant` conventions enforced by a unit test.
3. `ExternalRef` distinguishes immutable `externalId` from mutable `externalKey` (AD-14); the envelope type carries exactly the 11 canonical fields.
4. `MODULE.md` present, accurate (purpose, exported types, invariants, dependencies = none).
5. A change that introduces an outbound dependency from `eip-core` to another module **fails** the build (leaf-boundary demonstration — feeds the sprint demo).
