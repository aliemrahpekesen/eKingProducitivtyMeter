## Problem statement

The live `/api/v1` surface ships with no metrics, traces, or structured logs and no `traceId` on error bodies (DEBT-009, a G6 waiver). Add lean, production-grade observability: Micrometer RED metrics with `eip_*` names, OTel tracing exported to the existing Compose collector, JSON logs carrying the `traceId`/`spanId`/`tenantId` correlation key, and `traceId` in every problem+json — so a dashboard symptom is walkable to a trace and its logs (ObservabilityModel §2).

## Architecture constraints honored

- **Metric names + cardinality per ObservabilityModel §3:** `eip_api_request_duration_seconds` (tags `method, route, status`; **route = handler template, never raw path**) + `eip_api_requests_inflight`; common tag `deployable=eip-app`. Tenant is a `tenant_present` boolean — **never** the tenant id as a label (unbounded cardinality).
- **Correlation key (ObservabilityModel §2/§4):** `traceId`/`spanId` (from the OTel scope) + `tenantId` (from the tenant filter) on every request log line and on every problem+json.
- **Tracing (ObservabilityModel §4):** OTel SDK, **100 % SDK span export** (sampling is the collector's job), OTLP → the existing Compose collector (4318/HTTP); no new external collector dependency. Trace backend is optional — `traceId` still flows through logs/metrics when Tempo is absent.
- **Logs (ObservabilityModel §4 / BackendPlan §12.7):** structured JSON on stdout in `demo`/`prod` (Spring Boot 3.4 native `logging.structured.format=logstash`), human-readable in `local`/default; allow-listed bounded fields only — no secrets/PII.
- **Actuator (BackendPlan §12.6):** `health` (liveness/readiness probes), `info`, `prometheus` exposed.
- **No product-spec change; no new /api/v1 contract** — the OpenAPI snapshot is byte-identical (traceId lives only on error bodies, undocumented until DEBT-011). No frontend, no connectors, no AI, no RBAC/OIDC.

## Acceptance criteria

1. Actuator `health`/`info`/`prometheus` exposed; `health` reports `UP` (incl. db).
2. `eip_api_request_duration_seconds` + `eip_api_requests_inflight` emitted, tagged `method, route, status, tenant_present` + common `deployable`; the tenant id never appears as a metric label.
3. Structured JSON request log (demo/prod) with `traceId, spanId, tenantId, method, route, status, durationMs` (+ `errorType` where applicable).
4. `tenantId` (and trace ids) populated in MDC per request and **cleared** in a `finally` — no cross-request leak on pooled threads.
5. OTel tracing HTTP→service→JDBC via auto-instrumentation, OTLP-exported to the Compose collector; sampling probability 1.0 in the SDK.
6. Every problem+json response carries `traceId`.
7. Existing API/OpenAPI behavior unchanged (snapshot byte-identical).
