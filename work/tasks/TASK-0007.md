## Reconciliations (disclosed for G4/G8)

1. **Location — `.github/CODEOWNERS` vs root.** The task instruction and [TaskSpecs TASK-0007](../../sprints/sprint-00/TaskSpecs.md) direct `.github/CODEOWNERS`; [ModuleOwnership §4 note 3](../../engineering-operating-system/ModuleOwnership.md) and [RepositoryRules §7.1](../../engineering-operating-system/RepositoryRules.md) name the repository **root**. GitHub honors root, `.github/`, and `docs/` identically and the path mappings are unaffected. Placed at `.github/CODEOWNERS` per instruction; **flagged for R-CA** (the CODEOWNERS-change approver) to either ratify `.github/` by updating the two specs' "root" wording or move the file to root.
2. **Ordering — last-match-wins.** [RepositoryRules §7.3](../../engineering-operating-system/RepositoryRules.md) requires specific paths to follow their parents. §4's *listed* order places `/docs/adr/` **before** `/docs/`, which under last-match-wins would misassign ADRs to R-DE. Rules are reordered general→specific to honor the §1 map (verified: `docs/adr/*` → R-CA, `docs/architecture/generated/*` → R-BA, `docs/*` → R-DE). All §4 owner mappings are otherwise preserved verbatim.
3. **Coverage extensions (post-§4).** `/program`, `/sprints`, `/reviews` and the loose root files (`.editorconfig`, `.gitignore`, `CONTRIBUTING.md`, `LICENSE`) were created after §4 was authored. Owned per §1 principles: program & sprint-planning state → **R-TPM** (aligns with `/work` → R-TPM); architecture-readiness reviews → **R-CA**; repo-tooling dotfiles + Makefile → **R-DOA**; root docs → **R-DE**/**R-CA**. A leading `*` default owner encodes the [ModuleOwnership §6.3](../../engineering-operating-system/ModuleOwnership.md) "ambiguous → R-CA" rule, guaranteeing zero orphans (§6.1 / §7.4).
4. **Self-ownership.** Because the file lives under `.github/` (owned by R-DOA), an explicit `/.github/CODEOWNERS @eip/r-ca` rule (after `/.github/`) keeps the CODEOWNERS file itself governed by R-CA, matching §4's `/CODEOWNERS → R-CA` intent.
5. **R-SA not path-mapped.** Per [ModuleOwnership §4 note 2](../../engineering-operating-system/ModuleOwnership.md), security-sensitive files are covered by their owning module (e.g. `eip-tenancy` → R-BA+R-PA, `eip-app` → R-BA, `/infra`/`/.github` → R-DOA) plus CC-2 change-class routing to R-SA — not by a path rule. No orphaned security path results.
