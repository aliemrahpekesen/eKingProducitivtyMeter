## Problem statement

Make the persistence spine visible: a tenant-context filter that binds the request's tenant to the RLS GUC per transaction, and two read-only `/api/v1` endpoints — `session` (who am I / which tenant) and `connectors` (the connector registry with status) — served from the real RLS-protected database, deterministically. This turns the invisible control plane into something a customer can call and see.

## Architecture constraints honored

- **Deterministic, real DB reads** through RLS (`RlsTenantBinder` sets `app.tenant_id` per transaction; the DB enforces isolation).
- **No real Jira/Bitbucket/Sonar connectivity** — connectors are read from `core.connector`; demo rows are **simulation-seeded** (`simulation = true`), dev-profile only.
- **No full UI, no AI.**
- **Auth is not faked into a shortcut:** tenant resolution is behind a pluggable `TenantResolver`; the dev `HeaderTenantResolver` (reads `X-EIP-Tenant`) is **replaced by the OIDC token→tenant resolver in SPRINT-02** (P0-E3-S3). The filter and RLS binding are the real, permanent mechanism.
- Controllers live only in `eip-app` (BackendPlan §2.4); tenant-context state (`TenantContextHolder`) + the RLS binder live in `eip-tenancy`.

## Acceptance criteria

1. `GET /api/v1/session` returns the resolved tenant (id + organization name) for the request's tenant, 400/401 (RFC 7807) when no tenant is resolvable.
2. `GET /api/v1/connectors` returns the tenant's connectors (id, type, name, status, simulation) from `core.connector` **under RLS** — a request for tenant A never sees tenant B's connectors (integration-proven).
3. The read path binds the RLS GUC per transaction via `RlsTenantBinder`; an unbound request cannot read tenant data (fails closed).
4. OpenAPI 3 contract generated (springdoc) and committed; errors are RFC 7807 problem+json.
5. Demo data (a tenant + org + simulation connectors) seeds under the `demo` profile only; deterministic.
