- **branch:** `feature/TASK-0015-demo-hardening` off `integration/SPRINT-00`

- **intent:** remove the demo-UX gap the TASK-0014 review flagged — the demo tenant id was random per seed and had to be fetched from Postgres by hand. Make the demo load in one command with a fixed, well-known tenant.

## Problem statement

`DemoDataSeeder` used `UUID.randomUUID()` for the demo tenant, so a reviewer had to `SELECT id FROM core.tenant WHERE slug='demo'` and paste it into the UI. Give the demo a **fixed tenant id**, wire the frontend to default to it in demo mode, and add a **one command** (`make demo-up`) that brings up the whole local demo path.

## What changed (scope-limited)

- **Fixed demo tenant** — `DemoDataSeeder.DEMO_TENANT_ID = 00000000-0000-4000-8000-0000000000de` (was random). Stable across seeds; logged on seed for discoverability. **Demo-only** — production resolves tenants via OIDC and never references it. Seeder stays `@Profile("demo")` + idempotent.
- **Frontend demo default** — `frontend/.env.example` documents `VITE_EIP_TENANT_ID` = the fixed tenant (the app already consumes it). `make demo-up` injects it when launching the dev server, so the UI loads with **no DB lookup**. `.env.development` stays git-ignored (repo policy); nothing hard-codes a tenant in prod builds.
- **RLS role provisioning (dev-only)** — `infra/docker-compose/postgres/demo-roles.sql` creates the **`eip_app` NOBYPASSRLS** role and default privileges, so the local backend runs with **RLS fully enforced** (not as a superuser). The demo runs Flyway as the superuser (a dev shortcut, exactly as the Testcontainers harness does); production keeps the `eip_migrator`/`eip_app` split per DatabasePlan §2. **RLS is not weakened.**
- **One-command demo** — `make demo-up` / `make demo-down` (via `scripts/demo/demo-up.sh` / `demo-down.sh`): Postgres → provision role → build + start `eip-app` (`demo` profile, backgrounded, health-gated) → start the frontend with the tenant preloaded → open `http://localhost:5173`. `demo-down` stops the backend + Postgres. Runbook in [README](../../README.md) + [frontend/MODULE.md](../../frontend/MODULE.md).

## Honesty / guardrails held

- All seeded connectors remain `simulation = true` (`SIMULATION` badges); the persistent demo banner stays. No real connector ingestion, no AI, no OIDC/RBAC, **no new backend API endpoints**.
- No secrets committed (the demo role password `eip_app_dev_pw` is a dev-only credential in a dev-only init script, consistent with the existing `.env.example` dev creds — [DEBT-005](../debt-register.md)); no production behavior depends on the demo tenant.
