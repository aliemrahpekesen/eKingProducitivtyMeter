# TASK-0017 — Local Install & Environment Profiles (dev/test/preprod/prod)

- **id:** TASK-0017 · **sprint:** SPRINT-01 · **story:** founder goal — the existing platform must install and run end-to-end on a developer machine with one command, on macOS/Linux (`sh`) and Windows (`ps1`), with dev/test/preprod/prod managed by separate configs
- **branch:** `feature/TASK-0017-local-install-profiles` off `integration/SPRINT-00`
- **change class:** CC-7 (standard; touches BackendPlan §2.3 profile wording → ADR-022 records the scheme change)
- **assigned role:** R-DOA (install/runbook) + R-IE (backend config) under R-CA

## Scope

1. **Installer scripts** under `scripts/install/`: `install.sh` (macOS/Linux) and `install.ps1` (Windows) that stand up the FULL infra (Postgres, Redis, Kafka, MinIO+init, Keycloak, OTel Collector, Prometheus, Grafana via Docker Compose), provision the RLS `eip_app` role, build and start `eip-app` with the selected profile, start the frontend in the matching Vite mode, smoke-test the live endpoints, and print endpoints + sample-user info. Plus `stop.*` (stop apps + infra, keep data) and `uninstall.*` (down + volumes, destructive → confirmation). Makefile wrappers `install`/`stop`/`uninstall`.
2. **Environment profiles**: Spring profiles `dev`, `test`, `preprod`, `prod` with separate config files (`application-<env>.yaml`); `demo` stays as the data-seeding feature profile and is activated via profile groups by `dev` and `test`. Per-environment installer configs in `config/environments/*.env`; per-mode frontend configs `frontend/.env.{development,test,preprod,production}` (public values only).
3. **Docs-first reconciliation**: BackendPlan §2.3 ("exactly three profiles: local/demo/prod") is superseded by the founder-directed four-environment scheme → ADR-022 + BackendPlan edit + `docs/infrastructure/LocalInstall.md` runbook.

Out of scope (registered roadmap, unchanged): real connectors (DEBT-018), outbox/Kafka wiring (DEBT-017), OIDC/RBAC (DEBT-012 — therefore `prod` deliberately refuses to boot via `ProductionTenantResolutionGuard`; its config is complete and validated, the installer explains the guard), AI features.

## Acceptance

- `./scripts/install/install.sh --env dev` on a clean checkout brings up infra + backend + frontend, seeds demo data, and every existing function answers: `/api/v1/session`, `/api/v1/connectors` (paged), `/api/v1/friction/summary` (computed 91/56/50), `/api/v1/friction/teams/{id}/evidence`, actuator health/info/prometheus, OpenAPI, frontend UI incl. evidence drawer. Missing-tenant fails closed (401).
- `test` and `preprod` profiles boot green against the same infra; `prod` refuses with the documented guard message.
- All ports overridable; conflicts fail fast with exact override instructions.
- `install.ps1` mirrors `install.sh` 1:1 (prereqs, ports, flow); syntax-linted, not host-verified (no Windows/pwsh on this machine — noted honestly).
- Gates: `./gradlew check`, frontend gates, docs-lint green. Do not push.
