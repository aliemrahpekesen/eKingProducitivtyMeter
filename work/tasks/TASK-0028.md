# TASK-0028 — MinIO storage SPI (first real implementation)

- **id:** TASK-0028 · **sprint:** unassigned (claim when picked up) · **story:** ADR-027 §2 — implement the reserved-but-empty `com.eip.core.storage` package as a real MinIO-backed object-storage SPI, and prove it against the existing deterministic report path first.
- **branch:** create `feature/TASK-0028-minio-storage-spi` off `main` when claimed
- **status:** NOT STARTED — **blocked on [ADR-027](../../docs/adr/ADR-027-phase-3-ai-core-architecture.md) being Accepted.** Do not claim before then.
- **depends on:** none
- **closes:** part of DEBT-021 ("MinIO artifact storage")

## Scope

`com.eip.core.storage` is package-root-only today (`package-info.java`, zero interfaces) —
[ADR-007](../../docs/adr/ADR-007-minio-object-storage.md) already chose MinIO as the default
S3-compatible store, [ADR-018](../../docs/adr/ADR-018-object-storage-tenancy.md) already chose the
tenancy model above it. The MinIO *service* and its buckets (`eip-artifacts`, `eip-ingest`) already
run in dev infra (`infra/docker-compose/docker-compose.yml`) — only the Java client/abstraction is
greenfield. Build the storage SPI, then wire it into the **existing** deterministic `EXEC_SUMMARY`
report path (`ReportGenerationService`/`ReportRepository`) so `reports.generated_report.artifact_keys`
is populated for real — a low-risk, already-working caller to prove the SPI against before any
AI-composed report type needs it.

## Not in scope

`reports.report_job`/`report_template`/`report_schedule` (TASK-0029); any AI-composed report type
(TASK-0033). The deterministic `EXEC_SUMMARY` path's synchronous, on-demand-render behavior does not
change — it gains a real stored artifact in addition, not a new generation model.
