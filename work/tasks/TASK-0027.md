# TASK-0027 — LangChain4j swap behind the existing LLM SPI

- **id:** TASK-0027 · **sprint:** unassigned (claim when picked up) · **story:** ADR-027 §1 — swap `eip-ai`'s pure-JDK-`HttpClient` LLM provider implementations for LangChain4j-backed ones, behind the SPI shape M6-A already reserved for this.
- **branch:** create `feature/TASK-0027-langchain4j-swap` off `main` when claimed
- **status:** NOT STARTED — **blocked on [ADR-027](../../docs/adr/ADR-027-phase-3-ai-core-architecture.md) being Accepted** (currently Proposed, pending founder ratification). Do not claim before then.
- **depends on:** none (can be the first TASK claimed once ADR-027 is Accepted)
- **closes:** part of DEBT-021 ("adopt LangChain4j (ADR-006)")

## Scope

`com.eip.ai.spi.LlmClient.complete(LlmRequest) -> LlmResponse` does **not** change — its javadoc
already reserves this exact swap ("a LangChain4j-backed implementation becomes the default when
RAG/agent phases land"). Replace `com.eip.ai.providers`' `OllamaClient`/`OpenAiCompatibleClient`
(currently built on the shared `AiHttp` JDK-`HttpClient` helper) with LangChain4j-backed
implementations behind the same interface. `LlmClientFactory.forPolicy(...)`'s call sites
(`ExplainService`) do not change.

## Not in scope

RAG, agent orchestration, MCP, tool-calling — none of that exists yet (TASK-0031/0032). This is
purely an implementation swap under an unchanged contract.
