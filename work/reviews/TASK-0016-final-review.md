## Residual architecture / product risks

1. **Multi-version read-model ambiguity (MINOR-cluster).** `rm_team_friction_current` is keyed `(tenant, team, metric_version)` but the summary/evidence reads carry no `metric_version` filter — correct today (single version) but the first v0.2 computation would double rows. Must be fixed before any formula change.
2. **Single-source assumption in evidence.** The evidence JOIN on `core.external_ref` does not pin `source_system`/`source_instance`; a second identity provider for the same work item would fan rows out and break evidence-sum ↔ aggregate reconciliation. Must be pinned before the first real connector.
3. **Delete lifecycle dead-ends.** `op='delete'` raw records are dropped at normalization and soft-deleted items never resurrect — irrelevant for the append-only simulation, mandatory before real connectors (fold into the full lifecycle SPI work, DEBT-018).
4. **Nested tenant transactions** rebind the GUC without restore (PROPAGATION_REQUIRED join). No nested call site exists today and each stage runs its own transaction; a guard (reject nested with a different tenant) is cheap insurance when the orchestration grows.
5. **In-process synchronous transport** remains the accepted v0.1 simplification (DEBT-017): no backpressure/replay-from-log until the outbox lands.
6. **Simulation flag is constitutionally hardcoded** (`simulation=true` in the summary assembly) — honest today because the only source is the simulation connector; must become data-driven when real connectors land.
