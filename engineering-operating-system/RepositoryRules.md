# Repository Rules

This document is the binding rulebook of the EIP monorepo. Every engineering agent and human engineer reads it before their first commit and re-reads it whenever a rule is cited in review. It defines what may enter the repository, how, and by whom. Branch mechanics live in [./BranchingStrategy.md](./BranchingStrategy.md); path ownership in [./ModuleOwnership.md](./ModuleOwnership.md); the target tree in [./RepositoryStructure.md](./RepositoryStructure.md). "Engineering agent" here always means an agent that builds the product — never one of the product's 18 runtime agents ([../docs/ai/AgentArchitecture.md](../docs/ai/AgentArchitecture.md)).

## 1. Protected main and merge discipline

1. `main` is protected. Direct pushes are prohibited for every identity, including administrators. All changes land via pull request per [./BranchingStrategy.md](./BranchingStrategy.md).
2. Required status checks on every PR targeting `main` or `release/v0.N`: the automated portions of **G1** (build & static, incl. Modulith/ArchUnit boundary verification and OpenAPI diff), **G2** (tests + coverage ratchet), **G3** (SAST, dependency scan, secret scan, isolation tests), and **G7** (docs-lint), plus the `codeowners-coverage` check (§7). Conditional gates **G4/G5/G6** attach by declared change class (CC-1..CC-7) per [./QualityGatePolicy.md](./QualityGatePolicy.md).
3. Every PR MUST have **G8** approval from R-CR before merge. The author never merges without it; CC-1 changes additionally require the owning architect and R-CA (two-reviewer rule per [./QualityGatePolicy.md](./QualityGatePolicy.md) G8; review protocol in [./DevelopmentLifecycle.md](./DevelopmentLifecycle.md)).
4. Merge method is **squash only**; the squash commit message is a Conventional Commit `type(scope): summary [TASK-NNNN]` (types and scopes in [./BranchingStrategy.md](./BranchingStrategy.md) §5).
5. A PR MUST declare its change class(es) in the PR template. Misclassification is a BLOCKER verdict for R-CR.
6. CI is the only accepted truth for "tests pass". Claims of local success without a CI link are unverifiable and MUST be treated as BLOCKER per [./AIValidationWorkflow.md](./AIValidationWorkflow.md).
7. Every PR description carries exactly the canonical fields — task ref · change class(es) · what/why (≤ 10 lines) · contract impact (none | anchor diff summary) · test evidence (commands + results/CI links) · docs updated (paths) · observability delta · rollback note. A PR missing fields is returned without review.
8. Reverts are PRs too: `fix(scope): revert <original summary> [TASK-NNNN]`, same gates, same review. Only R-RM may expedite a revert on a `release/v0.N` branch, and the revert still requires green G1–G3.

## 2. Single-writer and write-set discipline

1. A task (`TASK-NNNN`) is CLAIMED by exactly one engineering agent at a time. One AI session ≈ one task claim.
2. Every task spec declares its **write-set** — the files/modules it may modify. A PR that touches files outside the declared write-set fails review unless the task spec is amended first by R-TPM.
3. Tasks scheduled in parallel within a sprint MUST have disjoint write-sets, or the sprint plan (`/work/sprints/SPRINT-NN.md`) MUST declare an explicit ordering between them.
4. Structural refactors are never concurrent with feature work in the same module ([./RefactoringPolicy.md](./RefactoringPolicy.md)). Boy-scout cleanups are allowed only inside the task's write-set.
5. A session that ends before DONE MUST write a handoff note to `/work/handoffs/TASK-NNNN-<seq>.md`. Undocumented state is lost by design ([./ContextManagementStrategy.md](./ContextManagementStrategy.md)).

## 3. Docs-first rule

1. The `/docs` tree is the documentation of record ([../docs/product/PRD.md](../docs/product/PRD.md) §7, constraint 6). Code MUST NOT silently diverge from it.
2. If an implementation must deviate from `/docs`, the doc change (plus an ADR when the deviation is decision-level, per [./ADRProcess.md](./ADRProcess.md)) lands **first**, or in the same PR for small clarifications. The doc diff is reviewed under G7 and, for contract anchors, G4.
3. Changes to contract anchors — [../docs/product/PRD.md](../docs/product/PRD.md), [../docs/architecture/DomainModel.md](../docs/architecture/DomainModel.md), [../docs/engineering/EventModel.md](../docs/engineering/EventModel.md), [../docs/engineering/APIDesign.md](../docs/engineering/APIDesign.md), [../docs/engineering/ConnectorFramework.md](../docs/engineering/ConnectorFramework.md) (SPI sections), [../docs/architecture/SecurityModel.md](../docs/architecture/SecurityModel.md) — are always **CC-1** and trigger G4 with R-CA.

## 4. Generated files — committed, never hand-edited

| Artifact | Location | Rule |
|---|---|---|
| OpenAPI document | generated by `:eip-app` build | Generated in CI (stage 5, [../docs/engineering/BackendPlan.md](../docs/engineering/BackendPlan.md) §16), **committed and diff-checked** per [../docs/engineering/APIDesign.md](../docs/engineering/APIDesign.md) §10; the openapi-diff gate blocks unannounced breaking changes |
| Frontend TS API client | `/frontend/src/api/generated/` | **Committed** so `pnpm dev` works offline; CI fails if stale relative to the OpenAPI document ([../docs/infrastructure/LocalDevelopment.md](../docs/infrastructure/LocalDevelopment.md) §5); never hand-edited |
| Spring Modulith documentation snapshots | `/docs/architecture/generated/` | **Committed** by the Modulith `Documenter` run ([../docs/engineering/BackendPlan.md](../docs/engineering/BackendPlan.md) §3); diffs reviewed as evidence of boundary changes |
| `pnpm-lock.yaml` | `/frontend` | **Committed**; CI installs with `--frozen-lockfile` ([./DependencyManagement.md](./DependencyManagement.md) §6) |
| Gradle dependency verification metadata | `/backend/gradle/verification-metadata.xml` | **Committed**; checksum verification per [./DependencyManagement.md](./DependencyManagement.md) §10 |
| Gradle version catalog | `/backend/gradle/libs.versions.toml` | Hand-maintained source of truth for all backend versions — not generated, but changes follow [./DependencyManagement.md](./DependencyManagement.md) |

Rules:

1. Generated artifacts MUST be regenerated and committed **in the same PR** as the change that invalidates them (`make api-client` after any controller/DTO change, per [../docs/infrastructure/LocalDevelopment.md](../docs/infrastructure/LocalDevelopment.md) §10).
2. Hand edits inside a generated path are a BLOCKER. Fix the generator or the source, never the output.
3. Generated and lock files are excluded from the PR size budget ([./BranchingStrategy.md](./BranchingStrategy.md) §4).

## 5. What may NEVER be committed

The following are prohibited in every branch, including short-lived ones. gitleaks runs on every PR (source, WireMock recordings, and simulation packs included — [../docs/testing/TestingStrategy.md](../docs/testing/TestingStrategy.md) security checklist); a hit is a hard failure and requires history rewrite plus credential rotation, escalated to R-SA.

- [ ] **Secrets and credentials** of any kind: API tokens, private keys, Keycloak client secrets other than the documented dev-only values in `.env.example` / `eip-realm.json` ([../docs/infrastructure/LocalDevelopment.md](../docs/infrastructure/LocalDevelopment.md) §3.1), cloud credentials, signed license files.
- [ ] **`.env` copies.** Only `infra/docker-compose/.env.example` is committed; the copied `.env` never is ([../docs/infrastructure/LocalDevelopment.md](../docs/infrastructure/LocalDevelopment.md) §2).
- [ ] **Real tenant or customer data** — real Jira/GitHub/SonarQube exports, real member names or identities, production database dumps. Development data comes exclusively from `/simulation` packs and recorded, redacted fixtures ([../docs/infrastructure/LocalDevelopment.md](../docs/infrastructure/LocalDevelopment.md) §7).
- [ ] **Unredacted logs, traces, or HTTP recordings.** WireMock/fixture recordings MUST be scrubbed of tokens, cookies, e-mails, and hostnames before commit.
- [ ] **Model weights or embedding models.** LLM/embedding models are delivered via the air-gap mirror bundle (NFR-051, [../docs/product/PRD.md](../docs/product/PRD.md)), never via git.
- [ ] **Build outputs**: `/backend/**/build/`, `/frontend/dist/`, `node_modules/`, container images, SBOM outputs (regenerated per build).
- [ ] **IDE state**, except the two committed exceptions: `.idea/runConfigurations/` (shared run configs) and `/scripts/idea/eip-codestyle.xml` ([../docs/infrastructure/LocalDevelopment.md](../docs/infrastructure/LocalDevelopment.md) §12).

## 6. Naming and size rules

| Item | Rule |
|---|---|
| Documentation files (`/docs`, `/engineering-operating-system`) | `PascalCase.md`, matching the fixed catalog names; new spec docs require R-DE approval |
| ADRs | `/docs/adr/ADR-NNN-slug.md` (three digits, kebab slug) |
| Work artifacts | `/work/tasks/TASK-NNNN.md`, `/work/sprints/SPRINT-NN.md`, `/work/handoffs/TASK-NNNN-<seq>.md` (zero-padded, monotonic) |
| Flyway migrations | `V<seq>__<snake_case_summary>.sql` (e.g. `V1__baseline.sql`) and repeatables `R__<object>.sql`, in `/backend/eip-app/src/main/resources/db/migration` only ([../docs/engineering/DatabasePlan.md](../docs/engineering/DatabasePlan.md) §7) |
| Java | packages `com.eip.<module>.*` exactly as tabled in [../docs/engineering/BackendPlan.md](../docs/engineering/BackendPlan.md) §1; classes `UpperCamelCase` |
| Frontend | feature folders lower-case under `/frontend/src/features/` per [../docs/engineering/FrontendPlan.md](../docs/engineering/FrontendPlan.md) §12; components `UpperCamelCase.tsx`; hooks `useX.ts` |
| Module charters | `MODULE.md` at each module root (one per backend module and `/frontend`) |
| SQL identifiers | `snake_case`, singular table nouns, index prefixes `ix_/ux_/fk_/ck_` ([../docs/engineering/DatabasePlan.md](../docs/engineering/DatabasePlan.md) §1) |
| Kafka | topics `eip.*`, consumer groups `eip.<module>.<purpose>`, DLQ `<group>.dlq` ([../docs/engineering/EventModel.md](../docs/engineering/EventModel.md)) — names live in constants, never string literals at call sites |
| Branches / commits | per [./BranchingStrategy.md](./BranchingStrategy.md) §2 and §5 |

Size limits (CI-enforced):

1. No committed file > **1 MB**. Anything larger belongs in object storage or is generated at build time.
2. Binary files only in allow-listed paths (`/docs/**/images/`, `/frontend/src/**/assets/`), each ≤ **200 KB**, and only formats reviewable as assets (png/svg/webp/woff2).
3. Simulation packs are committed as compact text definitions (JSON/NDJSON). An expanded dataset > **5 MB** MUST be produced by a committed generator script instead of being committed itself (the `enterprise-large` pack is generator-based).
4. PR size target ≤ **~400 net lines** excluding generated/lock files; larger requires declared justification in the PR description ([./BranchingStrategy.md](./BranchingStrategy.md) §4).

## 7. CODEOWNERS semantics

1. The root `CODEOWNERS` file (content in [./ModuleOwnership.md](./ModuleOwnership.md) §4) maps repository paths to engineering role IDs via team aliases `@eip/r-<xx>` (e.g. `@eip/r-ba` = R-BA). Branch protection enables *require review from Code Owners*: a PR touching an owned path cannot merge without the owning role's approval.
2. CODEOWNERS approval implements the **owning-architect leg** of G4/G8; it never replaces R-CR's independent G8 verdict.
3. Last-match-wins ordering is significant; more specific paths (e.g. the Flyway migration directory → R-DBA) MUST appear after their parent rules.
4. The `codeowners-coverage` CI check fails any PR containing a file that matches **no** CODEOWNERS rule (orphaned-code rule, [./ModuleOwnership.md](./ModuleOwnership.md) §6). A PR creating a new top-level path MUST extend CODEOWNERS and [./ModuleOwnership.md](./ModuleOwnership.md) in the same PR.
5. Changes to `CODEOWNERS` itself require R-CA approval and follow the transfer protocol in [./ModuleOwnership.md](./ModuleOwnership.md) §5.

## 8. Enforcement map

Every rule in this document is enforced by a named mechanism — a rule with no enforcement is a defect in this document, not a suggestion to readers.

| Rule | Enforced by | Gate |
|---|---|---|
| No direct pushes to `main` / `release/v0.N` | Branch protection | — |
| Required checks green before merge | Branch protection required status checks | G1, G2, G3, G7 |
| R-CR approval on every PR | Required review (1 approval minimum, non-author) | G8 |
| Owning-architect approval on owned paths | CODEOWNERS + *require review from Code Owners* | G4/G8 |
| Change-class declaration correct | R-CR verification (misclassification = BLOCKER) | G8 |
| Write-set respected | R-CR diff-vs-task-spec comparison | G8 |
| Docs-first / docs impact applied | docs-lint + docs-impact field check | G7 |
| Generated files current | OpenAPI diff check, client staleness check, Modulith docs diff | G1 |
| No secrets / prohibited content | gitleaks + repo content scan (file size, binary allow-list) | G3 |
| Naming conventions | Spotless/Checkstyle (Java), ESLint (TS), docs-lint (docs/work files), Flyway naming check | G1/G7 |
| Size limits (file, binary, PR) | CI `repo-hygiene` check + R-CR judgement on justification | G1/G8 |
| Every path owned | `codeowners-coverage` check | G1 |
| Regression test before fix | R-CR red→green evidence check on `fix` PRs | G8 |

## 9. Session bootstrap obligations

1. `/CLAUDE.md` at the repository root is the universal session bootstrap: every engineering agent reads it **first**, before the task spec. It links here and to [./EngineeringOperatingSystem.md](./EngineeringOperatingSystem.md).
2. An agent MUST NOT begin editing files before reading, in order: `/CLAUDE.md` → its task spec (`/work/tasks/TASK-NNNN.md`) → the task's context pack entries. The context pack is the only required pre-reading ([./ContextManagementStrategy.md](./ContextManagementStrategy.md)).
3. Durable knowledge produced during a session (decisions, gotchas, invariant discoveries) MUST be written into the appropriate layer — `/docs` + ADR (L1), `MODULE.md` (L2), or `/work` artifacts (L3) — before session end. Anything not written down is lost by design.

## 10. Common situations — the ruling

| Situation | Ruling |
|---|---|
| "My fix needs one line in a file outside my write-set" | Stop. Ask R-TPM to amend the task spec (fast path: comment on the task file, R-TPM approves in the PR thread). Never widen silently. |
| "gitleaks flagged a value in a test fixture" | Treat as real until proven otherwise. If a false positive, add a scoped gitleaks allow-list entry **in the same PR** with justification; R-SA approves the allow-list change. |
| "My PR is 900 lines and genuinely atomic" | Declare justification in the PR description; expect R-CR to test the claim against §4 split seams in [./BranchingStrategy.md](./BranchingStrategy.md). "It was faster this way" is not a justification. |
| "OpenAPI diff shows a breaking change I intended" | That is CC-1. Update [../docs/engineering/APIDesign.md](../docs/engineering/APIDesign.md) first (or same PR), declare the anchor diff in the contract-impact field, obtain G4 approvals. `/api/v1` is additive-only within v1 ([./VersioningStrategy.md](./VersioningStrategy.md)). |
| "CI is red on `main` after my merge" | Fixing it outranks all other work for the merging author; revert (rule §1.8) if not green within a working day. `main` MUST stay releasable. |
| "I found a shortcut worth taking" | Register-or-fix: take it only with a `DEBT-NNN` entry in `/work/debt-register.md` filed in the same PR ([./TechnicalDebtPolicy.md](./TechnicalDebtPolicy.md)). |
| "The spec is wrong / contradicts itself" | Do not code around it. File the discrepancy as a task or RISK entry, escalate to the owning architect; docs-first (§3) applies to corrections too. |
